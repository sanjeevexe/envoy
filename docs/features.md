# What works today

Every feature, what it does, and the evidence for it. How the models fit in is in [models.md](models.md); the
numbers are in [results.md](results.md).

| | What | Evidence |
| --- | --- | --- |
| **Agents call it** | MCP at `/mcp` (Streamable HTTP), 14 built-in tools: run a task or a routine, wait for it in the same turn (`wait_for_task`), post to several apps in one request, search memory, send a file to the phone, get files back, propose a trigger, list phones, read phone updates… Muse for Mac and the Muse app add it as a custom connector | [`backend/mcp_server/README.md`](../backend/mcp_server/README.md), [`docs/muse-link.md`](muse-link.md) |
| **Any MCP agent** | Muse; the Spark agent, a small agent on Meta's Muse Spark that reaches Envoy only over MCP; and any MCP client (Claude Code tested). Each has its own key and tool groups; every task says which agent asked | [`docs/agents.md`](agents.md), [`agents/meta-agent/evidence/2026-11-01/`](../agents/meta-agent/evidence/2026-11-01/) |
| **Learned tasks become tools** | Share a routine in Settings › Agents (off by default) and it appears in agents' tool lists under its own name, with typed inputs, no restart. In a Nov 2 dry run, Muse called the Reel, TikTok and Short routines by name, and each reached its final button, where it was declined | [`eval/results/agent-door/`](../eval/results/agent-door/) (`tools-before.json`, `tools-after.json`, `call.json`), [`eval/results/showcase/muse-2026-11-02/task-rows.json`](../eval/results/showcase/muse-2026-11-02/task-rows.json) |
| **App-only posts** | One clip from the Mac → an Instagram Reel with a library song, a Story with a poll sticker, a TikTok with a sound and a YouTube Short with a sound. All four went live on test accounts on the night of Nov 1, each started by the Spark agent and approved on the iPhone: the Reel, Story and Short with 0 model calls in Envoy's replay, the TikTok with 3. The agent that calls pays for its own turns: in a declined dry run on a test copy (Nov 1), the Spark agent used 11 model calls ($0.044) to drive three posts. Each was compiled by Muse Wonder from one agent run; the Story has needed no hand edits, and every edit to the others is [listed exactly](demo-showcase.md#hand-edits-stated-exactly) | [`docs/demo-showcase.md`](demo-showcase.md), [`data/routines/`](../data/routines/) (each `index.json`), [`agents/meta-agent/evidence/2026-11-01/crosspost/`](../agents/meta-agent/evidence/2026-11-01/crosspost/README.md) |
| **One request, every post** | In a Nov 4 take, Muse made one `cross_post` call for a Reel, a Short and a TikTok, and all three finished, at 0, 0 and 3 model calls in Envoy's replay. It runs the shared posting routines as one task with a part per destination, one after another. Each part ends done, failed, declined, waiting, outcome unknown (the post tap went through before its check) or not started, and a retry runs only the parts that didn't post; an outcome-unknown part is never posted again by itself. On Envoy's phone (Nov 2, a test copy, every final button declined): one request started four parts and returned in 0.26 s; three reached their final button and were declined, a YouTube search part finished, and a retry re-ran only those three | [`eval/results/agent-door/cross-post-pixel.json`](../eval/results/agent-door/cross-post-pixel.json), [`backend/tests/test_crosspost.py`](../backend/tests/test_crosspost.py), [`task-rows.json`](../eval/results/showcase/muse-2026-11-04/task-rows.json) and each routine's `index.json` (Nov 4) |
| **Watches** | A notification on Envoy's phone can start a task or reach the agent; each app is off until you allow it, and codes are hidden before anything is stored. An Instagram comment reached the iPhone 1.57 s after it landed on Envoy's phone. Plus time, email and changed-fact triggers, change alerts, and habits | [`docs/demo-showcase.md`](demo-showcase.md), [`eval/results/alerts/`](../eval/results/alerts/alerts.md), [`eval/results/recurring/`](../eval/results/recurring/recurring.md) |
| **Remembers** | A memory of what Envoy sees in apps, email and photos. Every fact keeps where and when it was seen, a newer source replaces an older value while the old one stays as history, and answers warn when a fact may be stale. Agents read it with `memory_search` and `memory_get` | [`backend/memory/README.md`](../backend/memory/README.md), [`memory.md`](../eval/results/final/memory.md) |
| **Learns** | In Envoy, a finished agent task's card has a "Make it a routine" button: Envoy compiles that run, replays it once strictly on the same phone, and saves it with the share off. Teach mode compiles what a person shows the same way, and the compiler can refuse a run. A routine has checks before and after its steps, targets found by what they are, a local repair when the app changes (the agent finishes if that fails), versions with a trial and a rollback | [`backend/routines/README.md`](../backend/routines/README.md), [`backend/api/teach.py`](../backend/api/teach.py) (`learn_task`) and its tests in [`backend/tests/test_teach.py`](../backend/tests/test_teach.py), [Results](results.md) |
| **Teach mode** | Do a task once through the live view; Envoy compiles it and replays it once before saving. A scripted Google Calendar lesson (7 steps) passed its verification replay, all 7 steps, with 0 model calls in Envoy's replay | [`site/data/recordings/teach.json`](../site/data/recordings/teach.json), [`eval/results/teach_trials_2026-11-01/`](../eval/results/teach_trials_2026-11-01/README.md) |
| **Phones** | "Envoy's phone" (a Pixel 5, Android 13, over USB) and emulators on the Mac; agents pick one with `list_phones`. A copy of Envoy on Google Cloud was tested too: routines for SkyLark (our test app) compiled on the Mac ran there 48/48 with no model calls, once the new emulator had finished its first boot | [`docs/phase-6-results.md`](phase-6-results.md), [`docs/cloud.md`](cloud.md) |
| **Cloud phone** | The same routines, compiled on the Mac, ran unchanged on an Android emulator on a Google Cloud server: 48 of 48 with no model calls (SkyLark, our test app, once the new emulator had finished its first boot). The whole learn-then-replay loop ran there too: one agent run, a routine compiled on the server, replayed 3 of 3 on bookings it had never seen | [`docs/cloud.md`](cloud.md) |
| **Siri and voice** | Press the iPhone's Action Button, say "Hey Siri, Ask Envoy" or tap a Control Center button, and say what you want. It's an Apple Shortcut, so it needs no app or developer account (tried on the iPhone, Oct 29). Dictation in the web app uses Muse Voice Transcribe | [`docs/siri.md`](siri.md), [`docs/phase-5-results.md`](phase-5-results.md) |
| **Offers and habits** | Envoy can offer before it acts ("Check in for SL 482?", one tap on Yes), notices what you repeat ("Make this a habit?"), and sets up recurring jobs you ask for in chat, switched off until you say yes | [`backend/api/offers.py`](../backend/api/offers.py), [`test_offers.py`](../backend/tests/test_offers.py) |
| **One question, two apps** | A request that needs two or more apps becomes one task with a part per app, and one answer | [`backend/api/crossapp.py`](../backend/api/crossapp.py), [`test_crossapp.py`](../backend/tests/test_crossapp.py) |
| **Before I start** | Before a task runs, Envoy says what to expect: the routine it will use and how long that usually takes, a past sign-in, a step that will need your OK | [`docs/preflight-and-autofill.md`](preflight-and-autofill.md) |
| **Saved logins** | The phone's own password manager fills a sign-in, so Envoy never sees, reads or types a password. Clean on both emulators and the Pixel; off by default | [`docs/preflight-and-autofill.md`](preflight-and-autofill.md) |
| **Real apps** | Envoy has run tasks in Amazon, Calendar, Chipotle, Chrome, Clock, Contacts, DoorDash, Gmail, Instagram, Lyft, Maps, the Play Store, Settings, Starbucks, TikTok, Uber, YouTube and YouTube Music. Apps that refuse emulators go to your own phone, asking first: Uber won't install on an emulator, so it runs on Envoy's phone. Target, whose bot check we saw, starts on that list, and Envoy adds an app itself when it sees a bot check or the Play Store refuses it | [`docs/real-app-test-set.md`](real-app-test-set.md), each routine's `index.json` in [`data/routines/`](../data/routines/), [`backend/api/routing.py`](../backend/api/routing.py) |
| **Files** | `send_to_phone` puts a Mac clip on the phone (a real phone waits for your OK); `get_file` gives the agent the final screen, the screen you approved, or a link from its own task | [`docs/muse-link.md`](muse-link.md) |
| **You approve** | An irreversible step that an agent or a trigger starts waits for your yes in Envoy on the iPhone, unless you set that routine to run without asking. When you ask Envoy yourself, your request is the yes ("Always ask" in Settings changes that). Spending money always asks. No agent has an approve tool; asked to approve, Claude Code and the Spark agent each said only you can | [`backend/policy/approval_rules.py`](../backend/policy/approval_rules.py), [`docs/agents.md`](agents.md) |
