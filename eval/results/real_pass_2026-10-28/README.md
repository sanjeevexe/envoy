- **starbucks, same input: pass → pass after repair (1 call).** The routine recompiled from Phase 7's trace still taps
  the recent search for the drink, and the app now lists "Caffè Latte" and "Caffe Latte" among five recent searches:

  before fix b. The hand-repaired v2 routine, the one the product library uses (`real_compiled/starbucks.yaml`), passes
  both inputs with no model call (extra row). New input (Caramel Macchiato, one recent search) passes strict in both.
- **amazon, new input: fail → wrong value.** Phase 7 found no price on the USB-C results page. This time a price
  matched, but from another row: the product is the XIAWAO 6-pack, and "$9.99 ( $5.00 /count)" is the 2-pack above it
  (XIAWAO shows $8.49). The routine reads product and price independently, so a page whose first row's price is split
  across elements yields a mismatched pair. Same cause class as Phase 7's miss (ads and split price labels); not counted
  as a pass.

## Found by this pass and fixed before the final run

The first attempt (on `84a0d00`) failed Chipotle on both inputs. Its zip field's after-check holds booking data ("City,
State, or ZIP: {{zip_code}} Veterans Memorial Highway…") and matched only relaxed after the repair typed the zip. The
next step is Back, which shows nothing to look for, and fix b's first version counted that silence as "wrong screen", so
the step typed again. The device layer's typing fallback then failed on the ADB keyboard (`ADB_KEYBOARD_CLEAR_TEXT`).
The rule now rejects a relaxed match only on evidence against the screen (`265177e`, with a test). Chipotle is back to
Phase 7's result. That attempt also saw play_rating's same input fail strict once, a slow Play Store home, and pass on
the next run.

## Flaky or for the user

- Starbucks' recent searches are app state. The repaired routine no longer depends on them, so nothing needs resetting
  before Nov 2.
- Typing fallback: when a tapped field never reports focus, `devices/android.py` falls back to uiautomator2's
  `send_keys`, whose ADB-keyboard broadcast can fail with no input connection; the step then fails outright instead of
  climbing the ladder. Not changed here.
